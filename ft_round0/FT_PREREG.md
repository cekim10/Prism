# FT Round 0 preregistration: survival-aware protection of beam-search KV state (FastTTS)

Frozen 2026-09-28 before any trace was collected. Thresholds are not to be changed afterwards.

## Question

In PRM-guided beam search served on a real AR generator with a KV cache, how much of the
*unique physical* KV byte-time that a uniform fault-tolerance policy would protect belongs to
branches the search itself is about to discard, and does that state die late and large enough
that losing it would be expensive to reconstruct?

Prism (dLLM, no KV cache, all pruning inside the first 8% of steps) gave 9-16% for the strict
oracle. FastTTS beam search prunes every iteration, so this is the workload where the idea gets its
one real chance. If the strict oracle stays below the gate here, the FT-search idea is closed
rather than hunting for a third workload.

## Workload and configuration

- Codebase: `ihc-fan-lab/FastTTS` at commit `1c01d54` (ASPLOS'26 artifact), vLLM 0.9.2.
- Generator `Qwen/Qwen2.5-Math-1.5B-Instruct`, verifier `Skywork/Skywork-o1-Open-PRM-Qwen-2.5-1.5B`
  (repo defaults), `gpu_memory_utilization` 0.45 each, prefix caching on, seed 42.
- Search: repo-default `SearchConfig` for `beam_search`: `n=8, beam_width=4` (keep `n/beam_width=2`
  per iteration), `num_iterations=40`, `temperature=0.8`, `top_p=1.0`, `max_tokens=2048`,
  `stop="\n\n"`, `agg_strategy="last"`, `lookahead=0`.
- `spec_beam_extension=False`, `prefix_aware_scheduling=False`, `offload_enabled=False`: the vanilla
  search semantics (one reasoning step per beam per iteration) so that the branch tree is exact.
  FastTTS's optimizations change scheduling, not which beams are pruned, and the KV accounting below
  already assumes ideal prefix sharing, which is what those optimizations approximate.
- Dataset: AIME 2024 (`HuggingFaceH4/aime_2024`, 30 problems, dataset order), the primary
  benchmark of the FastTTS paper. All 30 are run; if compute permits, MATH-500 problems 0-49 are
  added as a secondary, easier workload (reported separately, not pooled).

## Trace (per iteration, per beam)

`problem_id, iteration, uid, src_uid (beam it was copied from at this iteration, or itself),
step_tokens, total_completion_tokens, all_scores, agg_score, completed, pruned`, plus the prompt
token length once per problem, per-iteration generator and verifier wall time, and at the end the
uid of the returned `pred`. The traced `_beam_search` is a verbatim copy of the original with only
bookkeeping lines added; a static diff must show no other change.

## KV accounting (frozen)

Node = one reasoning step generated by one beam at one iteration; its unique physical KV is its
`step_tokens` x `bytes_per_token` (Qwen2.5-Math-1.5B: 28 layers x 2 KV heads x 128 x 2 (K,V) x
2 bytes = 28 KiB/token; reported also at a 7B-class 57 KiB/token, ratios are identical). The prompt
KV is shared by every beam, counted once per problem and needed under every policy. Duplicated
beams share all earlier steps with their source (prefix caching / CoW); only new steps are unique.

A node's KV is resident from its iteration `i` until the last iteration `d` at which any beam in
its subtree is still active (the prune decision at the end of iteration `d` frees it); a
completed beam's KV is freed at completion because the search keeps only its text and scores.
Residency is measured in iterations and in measured wall-seconds (per-iteration generator +
verifier time).

Policies, all applied to unique resident KV:
- `uniform`: protect every resident node.
- `oracle_strict`: protect a node iff its subtree contains a beam that completes (any candidate
  the search returns). Losing any other node cannot change the search outcome.
- `oracle_answer`: protect a node iff its subtree contains the returned `pred` (answer-preserving;
  descriptive only, needs a predictor of the final ranking).

## Primary metrics

```text
W_protect        = 1 - bytetime(oracle_strict) / bytetime(uniform)          <- PRIMARY (seconds-weighted; iteration-weighted reported too)
late_share       = share of the unprotected (eventually-pruned) byte-time whose death iteration d satisfies d / T_problem >= 0.5
C_recompute      = per dying lineage at its death: unique tokens below the nearest protected ancestor
                   (the tokens a recovery would have to regenerate/re-prefill); reported as median
                   tokens and as a share of that beam's full context (prompt + completion)
```

## Decision rule (frozen)

- **KILL**: `W_protect < 20%`.
- **GRAY**: `20% <= W_protect < 30%`.
- **KILL** (cheap recompute): `W_protect >= 30%` but the byte-time-weighted mean of
  `C_recompute / context` is below 0.20 or the median `C_recompute` is below 256 tokens.
- **FT candidate**: `W_protect >= 30%` and `late_share >= 50%`, recompute not cheap by the rule above.
- **GO**: FT candidate, and the same holds when protection is weighted by measured seconds
  rather than iterations.

Only the AIME 2024 run with the configuration above decides. No config search.

## Falsification tests

1. Traced beam search reproduces the untouched one: with the same seed, `pred`, completions and
   scores of the first 2 problems are identical (`--mode orig` vs `--mode traced`). vLLM sampling
   with a fixed seed is deterministic for identical request batches; if it is not on this stack,
   the test degrades to identical token counts per iteration and is reported as such.
2. Tree consistency: every node at iteration `i > 0` has exactly one parent at `i-1`; per iteration
   exactly `n` active beams before scoring; kept beams = `n/beam_width` unless fewer remain.
3. Unique-KV accounting: sum of step tokens over every returned beam's lineage equals that beam's
   `total_completion_tokens` (checked per problem).
4. Only resident state counts: nodes stop accruing byte-time at their subtree's last active
   iteration; completed beams accrue nothing after completion.
5. Iteration- and seconds-weighted results are both reported; the verdict uses seconds.
6. Descriptive online probe (not part of the rule): P(a kept beam's lineage is still kept at the
   next iteration) versus chance, to bound how predictable survival is from PRM rank alone.
